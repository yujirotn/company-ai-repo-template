# おすすめの設定（AI に何をさせて、何を止めるか）

この書庫には、AI（Claude Code・Codex）をこの書庫で使う時の「おすすめの設定」が最初から入っています。
SHO-SAN が実際に使っている守りを、どの会社でも使える形に直したものです。

この設定は**「うっかり」を防ぐためのもの**です。わざと抜け道を探す操作まで防ぐものではありません。
大事なデータを扱う時は、誰が何を見てよいかの管理（アカウント・権限の管理）も合わせて行ってください。

## 全体の形

AI が何かをしようとした時、次の3段で判断します。

| 段 | 意味 | 例 |
|---|---|---|
| 止める | 頼まれても実行しない。理由を日本語で出す | 鍵のファイルを読む・ホームフォルダを丸ごと消す |
| 確かめる | 実行する前に「よいですか」と人に聞く | GitHub へ送る・本番に反映する・メッセージを送る |
| 通す | 聞かずに実行する | ファイルを読む・一覧を出す |

置いてある場所:

| ファイル | 何か |
|---|---|
| `.claude/settings.json` | Claude Code の設定（止める・確かめるの一覧、見張り番の呼び出し、会社の道具） |
| `.codex/config.toml` | Codex の設定（書ける場所・確かめ方） |
| `.codex/rules/default.rules` | Codex で、止めるコマンド・確かめるコマンドの一覧 |
| `.codex/hooks.json` | Codex で、見張り番と「最新を取ってくる仕組み」を呼び出す設定 |
| `scripts/guardrail.py` | 見張り番。コマンドが動く直前に中身を見て、危ないものを止める（Claude Code・Codex 共通） |

## 1. 許可のモード（どのくらい聞いてくるか）

| 設定 | 何をするか | なぜか | 外したい時 |
|---|---|---|---|
| `"defaultMode": "default"` | ファイルを書き換える時・コマンドを動かす時に、毎回「よいですか」と聞く | 最初は、AI が何をしているかを目で見て覚えるのが一番安全 | 慣れてきたら、自分の `.claude/settings.local.json` に `"defaultMode": "acceptEdits"` と書く（ファイルの書き換えだけは聞かなくなる。コマンドは引き続き聞く） |
| `"disableBypassPermissionsMode": "disable"` | 「何も聞かずに全部やる」モード（bypassPermissions）を使えなくする | 公式も「外から隔離した環境（使い捨ての箱）の中だけで使うこと」としている。普段のパソコンで使うと、間違いを止める人がいなくなる | 外さないことをすすめます。どうしても必要なら、使い捨ての箱（コンテナ・仮想マシン）の中で、その箱だけの設定として使う |

SHO-SAN では、AI 専用に分けたパソコンを遠くから動かしているため「何も聞かずに全部やる」モードを使っていますが、
**普段のパソコンではすすめません。**

## 2. 止めるもの（Claude Code の `deny`）

### 秘密のファイルを読ませない

| 設定 | 何を止めるか | なぜか | 外したい時 |
|---|---|---|---|
| `Read(**/.env)` ほか `.env.local`・`.env.prod…`・`.env.dev…`・`.env.stag…`・`.env.test…` | 合言葉（API キー・パスワード）を書いた `.env` ファイルを読むこと | AI が読んだ中身は、会話の記録や外部のサービスに残ることがある | 外さない。見本は `.env.example`（中身は空の型だけ）に書けば、AI も読める |
| `Read(**/*.pem)`・`*.key`・`*.p12`・`*.pfx` | 鍵・証明書のファイルを読むこと | 鍵が漏れると、なりすましができてしまう | 外さない |
| `Read(**/*credentials*)`・`Read(**/*secret*)`・`Read(**/secrets/**)` | 名前に credentials・secret が入ったファイルを読むこと | 認証情報が入っていることが多い | 秘密ではないのにこの名前のファイルがある時は、名前を変える |
| `Read(**/id_rsa…)`・`Read(**/id_ed25519…)`・`Read(~/.ssh/**)` | サーバーにつなぐ鍵を読むこと | 鍵があれば、そのサーバーに入れてしまう | 外さない |
| `Read(~/.aws/**)`・`Read(~/.config/gcloud/**)`・`Read(~/.netrc)`・`Read(**/.npmrc)` | クラウド・道具のログイン情報を読むこと | 会社のクラウドを勝手に操作できてしまう | 外さない |

`Read` で止めたファイルは、`cat` などのコマンドで読むことも、書き換えることも止まります。

### 危ないコマンドを動かさない

| 設定 | 何を止めるか | なぜか | 外したい時 |
|---|---|---|---|
| `Bash(rm -rf /*)`・`Bash(rm -rf ~*)`・`Bash(rm -rf $HOME*)` | パソコンの大事な場所・ホームフォルダを丸ごと消すこと | 消したら元に戻せない | 外さない。一時フォルダを消したい時は、人が自分で消す |
| `Bash(sudo *)` | 管理者の権限で動かすこと | パソコン全体を変えられてしまう | 外さない。必要なら本人が自分のターミナルで実行する |
| `Bash(git push --force*)`・`Bash(git push -f*)` | 強制 push（GitHub の履歴を書き換えて送る） | みんなの書庫の履歴が消える | 外さない。必要な時は人が自分で実行する |
| `Bash(git commit --no-verify*)` | 保存前の確かめを飛ばして保存すること | 確かめで見つかった問題が、そのまま書庫に入る | 外さない。確かめで落ちた原因を直す |
| `Bash(curl *)`・`Bash(wget *)` | ネットとデータをやり取りするコマンド | 読んだページに「このデータを送れ」と書いてあった時に、そのまま送ってしまうおそれがある | ページを読むだけなら、AI の WebFetch（読むだけの道具）を使う。どうしても必要な仕事では、その仕事の書庫の設定で `ask` に移す |
| `Bash(nc *)`・`ncat`・`telnet`・`scp`・`sftp`・`ftp` | ほかのパソコン・サーバーへ、ファイルやデータを送るコマンド | 同上 | 同上 |

## 3. 確かめるもの（Claude Code の `ask`）

| 設定 | 何を確かめるか | なぜか | 外したい時 |
|---|---|---|---|
| `Bash(git push *)` | GitHub へ送ること | 送ったものは他の人にも届く。送り先の枝と中身を見てから | 自分の `.claude/settings.local.json` の `allow` に `Bash(git push -u origin feature/*)` のように、決まった形だけを足す |
| `Bash(rm -r *)`・`Bash(rm -rf *)`・`Bash(rm -fr *)` | フォルダごとまとめて消すこと | 何が消えるかを、消す前に見る | 外さない |
| `Bash(git reset --hard*)`・`Bash(git clean *)` | 手元の変更を消す git の操作 | まだ保存していない作業が消える | 外さない |
| `Bash(gh pr create *)`・`gh pr merge`・`gh pr comment`・`gh issue create`・`gh issue comment`・`gh release`・`gh repo create`・`gh api` | GitHub の上で、人の目に触れる操作 | 書いた文章や取り込みは、みんなに見える | よく使うものだけ、自分の `settings.local.json` の `allow` に足す |
| `Bash(ssh *)`・`Bash(rsync *)` | 別のパソコン・サーバーにつなぐ・送ること | 行き先がお客様のサーバーのこともある | 外さない |
| `Bash(npm publish*)`・`vercel`・`netlify deploy`・`firebase deploy`・`supabase db push`・`terraform apply`・`kubectl` | 本番への反映・世の中への公開 | `CLAUDE.md` の「本番を触らない」。指示があった時だけ | 外さない |
| `Edit(/.claude/settings.json)`・`Edit(/.codex/**)`・`Edit(/scripts/guardrail.py)` | AI が、自分の守りの設定を書き換えること | 守りを AI が自分で外せないようにする | 外さない。守りを変える時は、人が中身を見てプルリクエストで取り込む |

## 4. 見張り番（`scripts/guardrail.py`）

`settings.json` の一覧は「コマンドの頭の形」で判断するので、`cd x && rm -rf ~` のようにつないだ形や、
`git -C 場所 push` のような書き方では抜けることがあります。見張り番は、コマンドが動く直前に
**実際に動くコマンドを1つずつ取り出して**見て、次のものを止めます（止めた時は `[G01]` のような番号と理由を日本語で出します）。

引数や文章の中に同じ言葉が出てくるだけ（`echo "git push origin main"`・`grep "DROP TABLE"`・ファイルに書き込む文章の中身など）では止めません。

| 番号 | 何を止めるか | 判定 | なぜか |
|---|---|---|---|
| G01 | `rm -r` の相手が、ホームフォルダ・システムの場所・書庫の履歴（`.git`）・書庫の外・`*` | 止める | 消したら元に戻せない |
| G02 | 本体（`main`・`master`）への push・強制 push | 止める（`main` 以外への強制 push は確かめる） | 本体には直接入れず、枝からプルリクエストで入れる決まり |
| G03 | `git reset --hard`・`git clean -f`・`git checkout -- ファイル`・`git restore`・`git branch -D` | 確かめる | 手元の変更が消える |
| G04 | `sudo`・`--no-verify` | 止める | 管理者の権限・確かめ飛ばしは、人が自分でやる |
| G05 | データベースを壊す SQL（`DROP`・`TRUNCATE`・WHERE の無い `DELETE`・`UPDATE`）。`psql` などの道具と、データベースにつなぐ MCP の道具の両方 | 止める | 表の中身が全部消える |
| G06 | 秘密（`.env`・鍵・パスワードの道具）を取り出して、外へ送るコマンドに1つでつなぐこと | 止める | 読んだページに仕込まれた指示で、秘密が外へ出る一番素直な道だから |
| G07 | ネットから取ってきたものを、そのまま実行する（`curl … \| bash` など） | 止める | 中身を見ないまま、知らないプログラムが動く |
| G08 | 本番への反映・公開（`vercel --prod`・`firebase deploy`・`npm publish`・`terraform apply` など） | 確かめる | 「本番を触らない」決まり |
| G09 | MCP の道具（Slack・メール・カレンダーなど）で、送る・投稿する・消す・公開する | 確かめる | 送ったメッセージは取り消せない |

Codex では「確かめる」を出せないため、確かめるものも止めます（必要なら本人が自分のターミナルで実行します）。

**外したい時**: `scripts/guardrail.py` の `COMMAND_RULES` の一覧から、そのルールの行を消し、この表も直して、
プルリクエストで取り込みます。1回だけ必要な時は、AI にさせずに本人が自分のターミナルで実行してください
（Claude Code なら入力欄で `!` から始めると、本人の操作として動きます）。

動くか確かめる: `python3 scripts/guardrail.py --test`（止めるべきもの・通すべきものを全部試します）

python3 が入っていないパソコンでは、見張り番は動かず、何も止めません（AI の作業は止まりません）。
Mac は最初の1回だけ「コマンドライン・デベロッパ・ツール」を入れる確認が出ることがあります。

## 5. 書庫を開いた時に最新を取ってくる（今まで通り）

`SessionStart` の `scripts/pull-latest.sh` は、書庫を開いた時に GitHub から最新を取ってきます。
危ない操作（消す・書き換える）は一切しません。詳しくは `README.md` の「書庫の同期」を見てください。

## 6. Codex の設定

Codex は、この書庫を「信頼する」と答えた後にだけ、`.codex/` の設定を読みます。
`.codex/hooks.json` は、起動した時の「Hooks need review」で中身を確かめて信頼すると動きます。

| 設定 | 何をするか | なぜか | 外したい時 |
|---|---|---|---|
| `sandbox_mode = "workspace-write"` | AI が書けるのは、この書庫の中だけ | 書庫の外（パソコンの大事な場所）を書き換えない | 外さない。読むだけで十分な時は、起動時に `--sandbox read-only` |
| `approval_policy = "on-request"` | 囲いの外に出る操作の前に、人に確かめる | 公式がすすめる、対話で使う時の形 | 外さない。`never`（聞かない）は使い捨ての箱の中だけ |
| `network_access = false` | AI が自分でネットにつなぐのを止める | 送ってはいけないデータを送らない | 必要な時は、確かめの画面で人が許す |
| `.codex/rules/default.rules` の `forbidden` | `sudo`・強制 push・`--no-verify`・`curl` `wget` などの送信コマンドを止める | Claude Code の `deny` と同じ | 該当の `prefix_rule(...)` を消して、Codex を開き直す |
| `.codex/rules/default.rules` の `prompt` | `git push`・`git reset` `git clean`・`rm -r`・GitHub の上の操作・本番への反映・`ssh` `rsync` を確かめる | Claude Code の `ask` と同じ | 同上 |
| `.codex/hooks.json` の `PreToolUse` | 見張り番（`scripts/guardrail.py`）を動かす | コマンドの頭だけでは見抜けない危ない形を止める | `PreToolUse` の部分を消す |

ルールの効き方は、次のコマンドで確かめられます（例: `git push` が「確かめる」になるか）。

```bash
codex execpolicy check --pretty --rules .codex/rules/default.rules -- git push origin feature/x
```

**Codex で外せない形にしたい時**（会社のパソコンを管理している場合）: 書庫の中の設定は、本人が書き換えれば外せます。
「何も聞かずに全部やる」モード（`--sandbox danger-full-access` など）を会社として禁止したい時は、
管理者がパソコンの `/etc/codex/requirements.toml`（Windows は `%ProgramData%\OpenAI\Codex\requirements.toml`）に
`allowed_sandbox_modes = ["read-only", "workspace-write"]` などを書きます（書庫には置けません）。
Claude Code も同じく、外せない形にしたい時は管理者用の設定（managed settings）に `disableBypassPermissionsMode` を書きます。

## 7. 自分だけ変えたい時

書庫の設定（`.claude/settings.json`）はみんなで同じものを使います。自分だけ変えたい時は、
`.claude/settings.local.json`（書庫に入らない、自分のパソコンだけの設定）に書きます。
ただし、`deny`（止める）は、ほかの場所で `allow` と書いても外れません（止めるが一番強い）。
