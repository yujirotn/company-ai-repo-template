# ひな形の更新を取り込む

すでに会社の書庫を作っている人向けの手順です。手元にある**自社の書庫のフォルダ**で普段の AI を開き、下から合う方を選んで貼ってください。自社の書庫を変更できる GitHub アカウントを使います。プルリクエスト（変更の提案）ができたら、会社の人が差分を見て取り込みます。

## Codex に貼る文

```text
今開いている自社の書庫（作業先）の AGENTS.md を読んで。https://github.com/yujirotn/company-ai-repo-template の最新の main を参照用に取得し、この書庫と比べて、次の更新を自社の書庫に足して。

- members/ のおすすめの棚（members/_ひな形/ と members/見本/。skills/・hooks/・rules/・agents/・settings/・plugins/ の置き方、紹介、サンプル）
- 種類別の CATALOG.md と自動更新（scripts/catalog.py、.github/workflows/catalog.yml）
- README の「この書庫でやること3つ」と、この更新手順のリンク先（docs/ひな形の更新を取り込む.md）
- docs/運用ルール.md の棚と一覧の案内
- AGENTS.md と CLAUDE.md の部品ごとの「取り込む」「載せる」の決まり。スキルとエージェントはコピー、決まりは指示書に足す前に差分を確認、フック・設定は全文を本人に見せて本人が手で追加。プラグインは収録部品と入れ方を案内

ひな形側のファイルは差分を読むための資料として扱って。棚のフックや設定は見本として置き、自社や個人の実際の設定に足したり、有効にしたりしないで。

既存の会社名、DESIGN.md の内容、自社の plugins/、メンバーの名札や棚の部品、手元で作業中の変更は消さず、上書きもしないで。すでに同じ場所に文や設定があれば、差分を読み、必要な部分だけを足して。ひな形側への変更や、この書庫への一括マージはしないで。

自社の書庫の main を元に作業用の枝を作ってから編集し、python3 scripts/catalog.py で自社の部品一覧を作って。既存の CATALOG.md に手書きの紹介がある場合は、先に該当する棚の紹介に残してから再生成して。差分を確認し、今回の変更だけをコミットして、自社の書庫に枝を送って main 宛てのプルリクエストを作って。最後にプルリクエストの URL と確認結果を教えて。
```
