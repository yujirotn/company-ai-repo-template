# dev-pricing ─ 段7 価格（見積もり）

値段は「なんとなく」で決めると、後から変えにくいものです。
**費用から下の線を、お客様の感じ方から上の線を**出し、その間で決めます。

> **社内で使う道具なら、この段は飛ばしてかまいません。** 費用だけ知りたい時は「2. 費用を書き出す」だけ使えます。

## 始める前に

- `docs/00-コンセプト.md`（お金が払われている証拠）と、あれば `docs/05-検証.md`（払ってもよい金額の声）を読む
- `docs/03-データ.md` から、お金のかかるもの（外部サービス・AI の利用・置き先）を拾っておく
- 集計の道具: このスキルの `scripts/price_check.py`（Python だけで動き、外には何も送らない）。例のファイルは `assets/` にある

## 進め方

### 1. 何にお金を払ってもらうかを決める

「1人あたり月いくら」「1回いくら」「1社あたり」など、**値段の単位**を1つ推奨して確かめる。
単位は、お客様が得するものと一緒に増えるもの（使う人数・使う回数など）を推奨する。

### 2. 費用を書き出す（下の線）

`費用.csv` を作る（例: `assets/例_費用.csv`）。列は `項目,区分,金額`。

- 区分は「固定」（使う人が増えても毎月同じ。サーバー代など）か「1人あたり」（使う人1人に毎月かかる。AI の利用料・決済の手数料など）
- 金額は、各サービスの公式の料金表で確かめた数字か、試作で実際にかかった数字を入れる。**分からない所は推測で埋めず**、「（未確認）」と本人に伝えて、確かめる方法を添える
- AI の利用料は、1人が1か月に何回使うかの見込み × 1回あたりの料金で出す。見込みは多め（1.5倍など）に見る

### 3. プランの段と配分を決める

プランは3段（安い・ふつう・高い）を推奨する。お客様は真ん中を選びやすく、よく「2:6:2」（安い2割・ふつう6割・高い2割）の配分で見込みます。

- 真ん中のプランに、一番売りたい中身を入れる
- 一番上のプランは、真ん中を「ちょうどよい」と感じさせる役も持つ
- 一番下のプランでも、1人あたりの費用を下回らないようにする

`プラン.csv` を作る（例: `assets/例_プラン.csv`）。列は `プラン,月額,割合`。

### 4. 利益を試算する

```bash
python3 <このスキルのフォルダ>/scripts/price_check.py cost 費用.csv プラン.csv --users 100
```

使う人数を3通り（少ない・見込み・多い）で回して、表にする。「元が取れる人数」が見込みより多すぎないかを見る。

### 5. お客様の感じ方を聞く（上の線）

試作を見せた人や、使いそうな人に、次の4問を聞きます（Van Westendorp という、値段の感じ方の調べ方）。

1. いくらだと、安すぎて品質が不安になりますか？
2. いくらだと、安い（お得だ）と感じますか？
3. いくらだと、高いが、まだ買うか考えますか？
4. いくらだと、高すぎて買いませんか？

答えを `アンケート.csv`（列: `安すぎる,安い,高い,高すぎる`。1行が1人。数字だけ）にして集計する。

```bash
python3 <このスキルのフォルダ>/scripts/price_check.py vw アンケート.csv
```

出てくる「受け入れられる値段の幅」が上の線の目安です。人数が少ない（10人未満）時は、目安として扱う。

### 6. 決める

費用から出た下の線と、感じ方から出た幅を並べ、真ん中のプランの値段を推奨を添えて聞く。決めるのは本人。

## 終わりの確かめ

- `06-価格.md` の 1〜6 に中身がある。6 を本人が決めた
- 費用の数字に出どころが書いてある
- `00-コンセプト.md` の進み具合の「7 価格」に ○ と日付を入れ、次は `dev-design`（段8 デザイン）だと伝える

## 共通の決まり（どの段でも）

- **設計を変える時は、先に図面（docs）を直してからコードを直す**
- **直す前に、なぜそうなったか（根本原因）を説明してから直す**
- **分からないことは作らずに聞く**。1問ずつ、AI の推奨を添えて聞く（`grill` スキルが入っていれば使う）
- **鍵（パスワード・API キー・トークン・.env の中身）を docs にもコードにも書かない**。書くのは「どこに置いたか」だけ
