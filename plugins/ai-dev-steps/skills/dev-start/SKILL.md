# dev-start ─ 今どの段か・次は何か

開発の手順は、家づくりと同じで順番があります。先に図面（docs/）を描き、図面どおりに建て、最後に検査します。
後から思いつきで足すと、違法建築のように直すたびに別の所が壊れます。

このスキルは**何も作りません**。docs/ を見て「今どこか」「次に何をするか」を伝えるだけです。

## 手順 1〜9（家づくりのたとえ）

| 段 | やること | 家づくりでいうと | スキル | できるもの |
|---|---|---|---|---|
| 1 | コンセプト（誰の、どんな困りごとを、どう解くか） | 施主の要望を聞く | `dev-concept` | `docs/00-コンセプト.md` |
| 2 | 仕様（戦略・要件・構造の3層） | 要望書・構造と設備の仕様 | `dev-spec` | `docs/01-要件.md`・`docs/03-データ.md` |
| 3 | 画面（線だけの下書きを数案並べて選ぶ） | 間取り図・パース | `dev-wireframe` | `docs/02-画面.md`＋下書きの HTML |
| 4 | 試作（まず一通り動くもの） | 模型・モデルルーム | `dev-prototype` | 試作のコード＋`docs/04-完成条件.md`（試作の分） |
| 5 | 価値の検証（毎日使うか・無くなったら困るか） | 住む人に模型を見てもらう | `dev-validate` | `docs/05-検証.md` |
| 6 | 本番の実装（別の AI に厳しく点検させる） | 1部屋ずつ施工して検査 | `dev-build` | 本番のコード＋`docs/04-完成条件.md`（全部） |
| 7 | 価格（費用と利益の試算） | 見積もり | `dev-pricing` | `docs/06-価格.md` |
| 8 | デザイン（雰囲気→決まり→画面） | 内装・外観 | `dev-design` | 会社の `DESIGN.md` を当てる（無ければ `docs/デザイン.md`） |
| 9 | 攻撃して直す（自分の練習環境だけ） | 防犯の点検 | `dev-attack` | `docs/reviews/攻撃-<日付>.md` |

**5 と 7 は「売るもの」の時だけ**。社内で使う道具なら飛ばしてかまいません（`docs/00-コンセプト.md` の「種類」で決まります）。

## 判定のしかた

### 1. docs/ の場所を探す

1. 本人が仕事のフォルダ・入口の `README.md`・仕様の `docs/` の場所を示したら、そこを最優先する。相対パスは会話の作業フォルダを基準に確かめ、読み取れなければ場所を聞く。指定先に仕様がまだ無くても、別の仕事には切り替えない
2. 指定が無ければ、今いる場所が仕事のフォルダか、書庫の一番上かを `README.md` と書庫の決まりで確かめる。仕事の中で起動したらその仕事の入口を使う。書庫の一番上なら、その書庫の `projects/` の直下にある仕事の `README.md` と `docs/` を見る。`projects/README.md` は置き方の説明。仕事が複数なら候補を並べ、最近さわったものを推奨して1問だけ聞く
3. 書庫の親フォルダで起動した場合は、本人が示した書庫や仕事だけを見る。場所が分からなければ聞く。書庫の一番上の `docs/` は書庫全体の資料として扱う
4. 仕事がまだ無ければ段1（`dev-concept`）を案内する。本人が仕事の場所を示していれば、段1でそこに入口の `README.md` と `docs/` を作るよう案内する。指定が無ければ、仕事の名前を日本語で付けてもらって、書庫の `projects/<仕事の名前>/` に作るよう案内する。`projects/` が無ければ、段1で一緒に作る

### 2. 各ファイルが「埋まっているか」を見る

- ファイルが無い → まだ
- ファイルはあるが、見出し（`##`）の下が空・【　】が残っている → 書きかけ
- どの見出しの下にも中身がある → 済み

### 3. 進み具合の表を読む

仕事の `README.md` に「進み具合」の表と「最近の動き」があります。ファイルでは分からない段（4 試作・6 本番・9 攻撃）は、ここに各スキルが ○ を付けています。
ファイルの中身と表が食い違う時は、**点検・試験・本人の承認の記録を優先する**。中身が埋まっていても、本人の OK が確認待ちならその段で止める。食い違いは本人に伝える。

### 4. 次の段を決める

上から順に見て、最初に「まだ」「書きかけ」か「確認待ち」の段が次です。

1. `00-コンセプト.md` が済みでない → `dev-concept`
2. `01-要件.md` か `03-データ.md` が済みでない → `dev-spec`
3. `02-画面.md` が済みでない → `dev-wireframe`
4. 進み具合の「4 試作」が ○ でない → `dev-prototype`
5. 種類が「売るもの」で、`05-検証.md` が済みでない → `dev-validate`
   - 検証の結果が「戻る」なら、戻る先（1 か 3）を案内する
6. 進み具合の「6 本番」が ○ でない、または点検記録が「自己点検」のみ・試作のみ → `dev-build`
7. 種類が「売るもの」で、`06-価格.md` が済みでない → `dev-pricing`
8. 進み具合の「8 デザイン」と画面への適用の記録を確認する。使える決まりの場所は `dev-design` の「始める前に」に沿って確かめる。使える決まりが無ければ「決まりが未作成」、決まりがあって適用が確認できなければ「決まりはある・画面への適用が未確認」と案内する。適用済みでも本人の OK が無ければ「本人の確認待ち」と伝える。いずれも次は `dev-design`
9. 進み具合の「9 攻撃」と `docs/reviews/攻撃-<日付>.md` を確認する。コードを読む点検だけなら「一部（読む点検のみ）」と伝える。○ の表示があっても、記録が読む点検だけなら完了扱いにしない。別途の実地確認と修正後の確認の記録、重大・高0件、本人の承認がそろえば完了。それ以外で点検記録があるなら、その記録から残りの確認を伝える。点検記録が無ければ `dev-attack` を案内する
10. 全部済み → 「ひと通り終わりました」と伝え、直したい所があれば、図面（docs）から直すよう案内する

種類が書かれていない時は、5 と 7 を飛ばす前に「これは社内で使う道具ですか、売るものですか？」と1問聞く。

## 返し方

次の形で短く返す。長い説明はしない。

```
今の段: 3 画面（02-画面.md がまだありません）
済み: 1 コンセプト・2 仕様
飛ばす段: 5 価値の検証・7 価格（社内で使う道具のため）
次にすること: dev-wireframe スキルで、画面の下書きを数案作って選びます。
呼び方: 配置に合う呼び方を下から案内します。
```

- プラグインとして入れた場合、入口は Claude Code なら `/ai-dev-steps:dev-start`、Codex なら `$ai-dev-steps:dev-start`。次の段も同じ接頭辞で呼ぶ
- 書庫の `.claude/skills/` や `.agents/skills/` に直接置いた場合、Claude Code なら `/dev-start`、Codex なら `$dev-start`。次の段もスキル名だけで呼ぶ
- 親フォルダから起動してスキルが見つからない時は、対象の書庫か仕事のフォルダで新しく開く。同梱の `plugins/ai-dev-steps/skills/dev-start/SKILL.md` をパスで示し、「この手順で進めて」と頼む方法もある

本人が「次へ進んで」と言ったら、そのスキルを読んで始める。

## 途中から入る・戻る

- すでにコードがあって docs が無い仕事: 段1でコードを読み、分かることを docs の下書きにするよう案内する
- 前の段に戻りたい時（例: 試作を見て画面を変えたい）: 戻ってよい。戻った段の docs を直し、その後ろの段で影響を受ける所を本人に伝える
- 仕事の `README.md` が無い時（ほかの道で作った docs など）: docs から今の段を読み取り、次に着手する段で入口の `README.md` を作るよう案内する

## 共通の決まり（どの段でも）

- **設計を変える時は、先に図面（docs）を直してからコードを直す**
- **直す前に、なぜそうなったか（根本原因）を説明してから直す**
- **分からないことは作らずに聞く**。1問ずつ、AI の推奨を添えて聞く（`grill` スキルが入っていれば使う）
- **鍵（パスワード・API キー・トークン・.env の中身）を docs にもコードにも書かない**。書くのは「どこに置いたか」だけ
- **段の終わりは、本人の OK が出るまで次の段へ進まない**。AI が推奨で決めた所は「（推奨で決めた・本人の確認待ち）」と書き、OK をもらったら外す。方向を変えたいと言われたら、その段か前の段の docs から直す
- **段が進んだ・決めたことがあった時は、仕事の `README.md` を直す**: 進み具合の表と「今の段」を直し、「最近の動き」の一番上に `- 日付: 何をしたか・決めたこと` を1行足す
