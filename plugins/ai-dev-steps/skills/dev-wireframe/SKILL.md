# dev-wireframe ─ 段3 画面（間取り図・パース）

家の間取り図と同じで、色や飾りは付けず、**どこに何のかたまりを置くか**だけを線で描きます。
1案だけだと良し悪しが分からないので、**違う考え方の案を3つ**並べて選んでもらいます。

デザインの専用の道具は要りません。AI に線だけの HTML を描かせれば、ブラウザで見られる見本になります。

## 始める前に

- `docs/01-要件.md` と `docs/03-データ.md` を読む。無ければ「先に dev-spec をやりましょう」と伝える
- 画面の数と、各画面の「主な作業（1つ）」を先に書き出して本人に確かめる（例: 一覧画面＝今どこに何があるかを見る）

## 進め方

1. **画面の一覧を決める**: 各画面の名前・主な作業・誰が使うか。画面は少ないほどよい（最初は1〜3画面を推奨）
2. **3案を作る**: いちばん大事な画面について、考え方の違う3案を作る。例:
   - 案A 一覧が主役（表で全部見せる）
   - 案B 探すのが主役（検索の箱が一番上）
   - 案C 今日やることが主役（自分に関係あるものだけ）
3. **1枚の HTML にまとめる**: `docs/wireframes/画面案.html`。上にタブ（案A・案B・案C）を置き、押すと切り替わる。各案の下に「この案の考え方」「向いている人」を2行で書く
4. **見せる**: ブラウザで開いて本人に見てもらう。共有ページを作れる道具があれば、それで URL にして渡す（本人が別の場所から見られるように）
5. **選んでもらう**: 「私なら案◯です。理由は〜」と推奨を添えて聞く。「案Aの一覧＋案Cの絞り込み」のような組み合わせも受け付ける
6. **残りの画面**: 選んだ考え方で、ほかの画面も線だけで描き、同じ HTML に足す
7. **`02-画面.md` に書く**: 下の型で。選ばなかった案と理由も残す（後で迷い直さないため）

## 下書きの HTML の決まり

- 色は白・灰・黒だけ。飾り・写真・アイコンは使わない（四角と文字だけ）
- 文字は実際に出る言葉で書く（「テキスト」「ダミー」と書かない。例: 「プロジェクター（会議室B）」）
- 大事なものの目立たせ方は、色に頼らず、大きさ・太さ・枠で示す
- スマホでも使うなら、横幅の狭い版も並べる
- 外のファイル（画像・フォント・ライブラリ）を読み込まない。1つのファイルで開ける
- 本物の個人情報・社内の数字を入れない（架空の例にする）

## `02-画面.md` の型



```markdown
# 画面

> 間取り図のつもりで、画面の数・各画面に出すもの・画面同士のつながりを先に描く。コードより先にここを埋める。

## 1. 画面の一覧
| 画面 | 主な作業（1つ） | 使う人 | パソコン／スマホ |
|---|---|---|---|

## 2. 各画面に表示するもの
（画面ごとに、上から順に箇条書き。最初に目に入るべきものを一番上に）

## 3. 画面同士のつながり（どこからどこへ進めるか）

## 4. 画面見本
- 下書き: `docs/wireframes/画面案.html`（選んだのは案◯）

## 5. 選んだ理由・選ばなかった案
| 案 | 考え方 | 選んだ／選ばなかった理由 |
|---|---|---|
```

画面ごとに、もっと細かく決めたい時（お手本にする既存の画面・合格条件など）は、`ux-review` スキルが入っていれば、その「設計」のやり方を使ってよい。

## 終わりの確かめ

- `02-画面.md` の 1〜5 に中身がある
- HTML がブラウザで開け、タブで3案が切り替わる
- 本人が案を選んだ（選んだ案が `02-画面.md` に書いてある）
- 仕事の `README.md` の進み具合の「3 画面」に ○ と日付を入れ、次は `dev-prototype`（段4 試作）だと伝える

## 共通の決まり（どの段でも）

- **設計を変える時は、先に図面（docs）を直してからコードを直す**
- **直す前に、なぜそうなったか（根本原因）を説明してから直す**
- **分からないことは作らずに聞く**。1問ずつ、AI の推奨を添えて聞く（`grill` スキルが入っていれば使う）
- **鍵（パスワード・API キー・トークン・.env の中身）を docs にもコードにも書かない**。書くのは「どこに置いたか」だけ
- **段の終わりは、本人の OK が出るまで次の段へ進まない**。AI が推奨で決めた所は「（推奨で決めた・本人の確認待ち）」と書き、OK をもらったら外す。方向を変えたいと言われたら、その段か前の段の docs から直す
- **段が進んだ・決めたことがあった時は、仕事の `README.md` を直す**: 進み具合の表と「今の段」を直し、「最近の動き」の一番上に `- 日付: 何をしたか・決めたこと` を1行足す
