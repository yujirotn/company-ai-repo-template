# 仕様書から始める

後から機能を足すと、作りが歪みます（違法建築と同じです）。コードを1行も書く前に、
**4つの仕様書**を先に埋めてから着手してください。

## 手順

1. `projects/<仕事の名前>/docs/` フォルダがまだ無ければ作る。
   `projects/_ひな形/docs/` の4ファイル（`01-要件.md` `02-画面.md` `03-データ.md` `04-完成条件.md`）を
   そのままコピーする（空の型を複製する。中身は書き換えない元の`_ひな形`はそのまま残す）
2. 聞き役になって、ユーザーに1つずつ質問し、答えを各ファイルに書き込む。
   **先にコードを書かない。仕様書が埋まってから着手する。**
3. 4つのファイルを順番に埋める。各ファイルの質問の型は以下を使う（アレンジしてよいが、
   抜け漏れがないか必ず確認する）。

### `01-要件.md` を埋める質問

- これは何のための仕事か（1〜2文で）
- 誰が使うか（役職・人数）
- 誰が何を見て、何を決めるか（画面ごとの「見る人」「決める人」）
- 誰が見てよいデータで、誰に見せてはいけない数字があるか（金額・個人情報など）
- いつまでに、何ができれば最初のゴールか

### `02-画面.md` を埋める質問

- 画面はいくつあるか。それぞれ何のための画面か
- 各画面に何を表示するか（箇条書きでよい。間取り図のつもりで）
- 画面と画面はどうつながるか（この画面からどこへ進めるか）
- スマホでも見るか、パソコンだけか

### `03-データ.md` を埋める質問

- データはどこから来るか（入力・既存のシステム・外部サービス）
- 外部サービスに接続するなら、接続キー（APIキー・パスワード）は何が必要か
  - **接続キーの値そのものは、この仕様書にも書庫にも書かない**。
    「キーが必要」という事実と、どこに保管するか（`.env` ファイル・秘密情報の保管サービスなど）だけ書く
- データはどこに保存されるか。誰が見られるか

### `04-完成条件.md` を埋める質問

- 何ができたら「完成」と言えるか（具体的な操作と、期待する結果のセットで）
- 守りの条件は何か（例: 鍵がコードに無い・ログイン無しで開けない・本番を壊していない）
- 誰が完成を確認するか（作った人以外の、確かめる役を必ず立てる）

## してはいけないこと

- 仕様書を埋める前にコードを書き始める
- 接続キーやパスワードの実際の値を仕様書に書く
- ユーザーに一度にすべての質問をぶつける（1つずつ聞き、答えを都度書き込む）

## 次にすること

4つの仕様書が埋まったら、小さく作って確かめる段階に進む。変更を保存するときは
`save-to-archive` スキルを使う。
