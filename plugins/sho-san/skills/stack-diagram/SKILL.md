# stack-diagram — 構成図を描く

クラウド事業者の構成図のような図を作る。白いタイルに実物のロゴ、サービスのまとまりを囲む枠、直角に折れる矢印と等幅のラベル、方眼紙の背景。
**1枚の自己完結HTMLが正本**で、PNG・TSX・公開ページはそこから作る。

## この会社で使う時の決まり

- 作り始める前に、書庫の一番上の `CLAUDE.md`（置き場所・守ること）と `DESIGN.md`（会社のデザインの決まり）を読む
- この図の見た目（角丸・色付きの枠・方眼の背景）は、エンジニア向けの構成説明に向く。**お客様に渡す読み物に貼る図は `explain-visual` スキルで、`DESIGN.md` の色に合わせて描く**
- 作業中のファイルは作業用の一時フォルダに置き、使うと決めた図だけをその仕事の場所（例: `projects/<名前>/docs/`）に移す
- 図に**お客様の名前・社内のサーバー名・IPアドレス・社内のチャンネル名・非公開の書庫名**を入れたら、その図を外に出さない。外に出す図は、それらを消して描き直す
- **図を外部のサイトへ投稿・共有しない**（元のスキルにあった公開ギャラリーへの投稿機能は外してある）
- ロゴの取得は外部サイトから画像を読み込むだけで、こちらの情報は送らない。取得したファイルを動かす時は `python3 -I` で実行する

## 必要なもの

- Python 3.9 以上（`fetch_icons.py`・`build.py` は標準ライブラリだけで動く）
- ロゴを取りに行くネット接続（svgl.app・raw.githubusercontent.com・cdn.jsdelivr.net・AWS の公式アイコン置き場、`name=URL` で指定したサイト）
- PNG を作る時は Playwright と Chromium: `pip install playwright && python3 -m playwright install --with-deps chromium`
- 書体は同梱しない。Geist / JetBrains Mono が入っていれば使い、無ければ OS の書体で表示される（日本語は Hiragino / 游ゴシック / Noto Sans JP の順）

## 手順

1. 中身を決める（ノード・まとまり・矢印）
2. ロゴを集める — `scripts/fetch_icons.py`
3. 座標を決める — `references/geometry.md` を読む
4. `assets/template.html` からHTMLを組む — `scripts/build.py`
5. **PNG にして自分の目で見る**（渡す前に必ず）
6. 頼まれた形で渡す

## 1. 中身を決める

- **ノード**: 技術・サービス1つ＝1ノード（名前＋短い役割。例 `http server`・`sqlite db`）
- **まとまり（グループ）**: 同じ実行環境・同じ事業者・同じ書庫のものを枠で囲む。入れ子は1段まで。枠の名前は、そのブランドの正式な書き方（`GitHub`・`npm`）で書く
- **矢印は3種類**:
  - 強調色の実線＝主な依頼・データの流れ（1本の続いた道にすると読みやすい）
  - 灰色の実線＝内部のつながり
  - 灰色の点線＝開発時・反映時の関係（CI・git hook・IaC での反映）

技術の名前を並べただけで渡されたら、それぞれが何者かから、まとまりと流れを推し量って描く。どちらに描いても図が間違いになるほどあいまいな時だけ聞く。

## 2. ロゴを集める

```bash
python3 scripts/fetch_icons.py <アイコン置き場> tanstack hono drizzle "betterauth:better-auth" "orpc=https://orpc.unnoq.com/logo.webp"
python3 scripts/fetch_icons.py <アイコン置き場> "aws:aws/AWS-Cloud-logo" "vpc:aws/vpc" "fargate:aws/fargate" "s3:aws/s3"
```

指定の書き方: `name`（名前をそのまま探す）／`name:slug`（探す名前を変える）／`name=URL`（URL を直接指定）／`name:aws/<Name>`（AWS の公式アイコン）／`name:lucide/<icon>`（線のピクトグラム）。
探す順は **svgl → devicon → gilbarbara/logos**。ファイルと `manifest.json` を書き出し、白い塗りのロゴには印を付ける。明暗2種類あるロゴは、明るい方を `<name>`、暗い方を `<name>_dark`（枠の名前用）として保存する。

仕組みより大事な決まり:

- **ロゴの色を変えない。** 白や薄すぎて白いタイルで見えないロゴは、色を変えずに暗いタイル（`tile dark`）に載せる。`white_fill` の印は目安なので（色付きのロゴの中の白い部分にも付く）、暗いタイルにする前に SVG を一度見る
- **公式のロゴだけ使う。** 単色で描き直したアイコン集は使わない（見る人はすぐ気づく）。どこにも無い（`FAIL`）時は、そのサービスの書庫（`logo*.svg`・`docs/`・`assets/`・`public/`）やサイト（`/logo.svg`・`/favicon.svg`）で公式のファイルを探して `name=URL` で渡す。公式サイトの `<link rel=icon>` の URL でもよい
- **ブランドの無い概念はピクトグラムで。** 「開発環境」「定期実行」「キュー」「キャッシュ」「Webhook の受け口」などは `name:lucide/<icon>`（例 `devenv:lucide/terminal`・`cron:lucide/clock`）。タイルに文字を書かない・絵文字を使わない
- **同じ会社の別製品**（Cloudflare D1・R2 など）はロゴが同じことが多い。会社のロゴを使い、違いはノード名で示す
- **AWS は AWS の公式アイコン**を `name:aws/<Name>` で取る（`s3`・`sqs`・`ecs`・`alb`・`vpc` などの略称も通る。見つからない時は名前の一覧が出る）。サービスには必ず `aws/` を付ける。AWS のアイコン一式は図に使うのは許されているが、再配布は未確認なので書庫に入れない
- **AWS の図は AWS の描き方に合わせる。** アイコン自体に四角があるので `tile bare`（白タイルを重ねない）。人や汎用のものは AWS の汎用アイコン（`user:aws/General-User` など）を `tile bare res` と `lt`/`dk` の組で。枠は `group aws`（ラベルに AWS Cloud のロゴ）と `region`・`az`・`vpc`・`private`・`public`。VPC の中は、分かる・無理なく推せる時は公開／非公開のサブネットに分ける。矢印は1色で開いた矢じり（`class="aws"`・`marker-end="url(#open)"`）、開発・反映は `aws dash`、凡例は付けない。ノード名は `Amazon S3`・`AWS Fargate` のように正式名で、`ALB` のような略称は役割の行に書く。2行になる時も `Amazon`／`AWS` は最初の語と同じ行に置く（折れるならノードを広げる: `left:<中心X-76>px; width:152px`）
- **ブランドでないもの**（利用者・ブラウザ・インターネット・端末・物理サーバー）は `assets/generic/` の絵をアイコン置き場にノード名でコピーするか、`name:lucide/<icon>` を使う。これらは図の文字色に染めてよい
- **枠の名前に付くアイコンは 14px**。横長のロゴ（文字ロゴ）は潰れるので、正方形のマークを別に取る
- **枠の名前は枠の薄い地の上に載る**ので、暗い表示では黒い部分のあるマークが消える。`<name>_dark` があれば `lt`/`dk` の組を使い、無ければ `<img>` に `plate` を付ける
- png・webp のロゴも使える。組み立て時に全部 data URI で埋め込むので、表示時に外へ取りに行かない

## 3. 座標を決める

`references/geometry.md` を読む。座標の決め方・間隔の決まりと、**矢印がラベルの文字を突き抜けないための付け方**が書いてある。
要点は1行: **ノードは「タイル＋その下の文字」までがひとかたまり。縦の矢印はそのかたまりの境目につなぎ、文字を通してタイル同士を結ばない。**

## 4. 組み立てる

`assets/template.html` を複製し、見本の GROUPS / EDGES / NODES / 見出し部分を自分の中身に置き換える（見本の書き方がそのまま書式の説明になっている）。
`<html>` の `lang` はラベルの言語に合わせる（日本語なら `ja`。日本語の字形で表示させるため）。

テンプレートに入っている2つの使い方:
- **暗い表示**: `<html>` に `data-theme="dark"`。タイルは白のまま、矢じりと凡例は自動で追従する
- **「X に反映する」矢印で X が枠の時**: 枠の中の代表的なノードに矢印を向け、ラベル（`deploy`）を付ける

```bash
python3 scripts/build.py my-diagram.html <アイコン置き場> out.html
```

アイコンはマークアップの中で `%%ICON_<name>%%` と書く。解決できない記号が残ると組み立ては止まる。
**色と書体はテンプレートの CSS 変数（トークン）だけで変える**。ばらばらに値を書かない。会社の色に寄せる時は `DESIGN.md` の色をトークンに入れる。

## 5. 見て確かめる

```bash
python3 scripts/render_png.py out.html check.png --selector .canvas --scale 2
```

日本語を含む図は、撮るパソコンに日本語の書体が要る。無いと中国語の字形で出る（見る人はすぐ気づく）。スクリプトが警告と直し方を出す。

見る時の点検:
- 矢印がラベルの文字を横切っていない／矢じりが文字の中に刺さっていない
- 矢印のラベルが読める（背景色の縁取りが効いている）
- すべてのアイコンが見える（白地に白は定番の失敗→暗いタイル）。暗い表示の枠の名前のアイコンも
- 枠の名前が枠の左上にあり、ノードや矢印と重ならない。枠の左右の余白がそろっている
- 枠からはみ出すもの・画面の端で切れるものが無い

直して撮り直すのを、きれいになるまで繰り返す。この繰り返しは安い。文字が重なった図を渡す方が高くつく。

## 6. 渡す

- **HTML**（基本）: 組み立てた1枚。外へ取りに行かず、ネットが無くても開ける
- **PNG**: 必ず組み立てたHTMLを Chromium で撮って作る（`render_png.py`・`--scale 2`）。別の道具で絵を描き直さない（HTML が正本）。標準で明るい表示（`out.png`）と暗い表示（`out-dark.png`）の両方を、角を直角にして撮る。頼まれなければ両方渡す。`--single` は書いたままの表示を1枚、`--full-page` はページ全体
- **TSX**: `references/tsx.md` に従って React 部品にする（依存なし）
- **ページとして見せる**: 使っている環境にページ公開の道具があれば、組み立てたHTMLをそのまま渡せる（中身は全部埋め込み済み）。公開してよいかは、上の「この会社で使う時の決まり」に照らしてから

いくつかの形を頼まれたら、HTML を1回作ってそこから全部作る。

フッターには、実際に使ったアイコンの出どころ（`manifest.json` の各 `source`。例 `icons: svgl / devicon / Lucide`、`aws` は `AWS Architecture Icons`）を書く。ブランドのロゴはそれぞれの持ち主の商標。テンプレートの「made with stack-diagram」のリンクは、頼まれない限り残す（元の作者への表示。PNG は図の部分だけ撮るので写らない）。
