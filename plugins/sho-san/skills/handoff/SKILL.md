# handoff ─ README に引き継ぎを残す

AIは会話が変わると、前の会話を覚えていない。だから**続きに必要なことは、会話ではなくファイルに残す**。
このスキルは、その「残す」を毎回同じ形でやるための手順。

## どの README に書くか

会話の中身から決める。迷ったら、作業していたファイルに一番近い README。

| やっていたこと | 書く場所 |
|---|---|
| 仕事（プロジェクト） | `projects/<仕事の名前>/README.md`（無ければ作る） |
| 部署の道具づくり | `plugins/<部署名>/README.md` |
| 自分だけの試作・メモ | 自分の個人の書庫の README（`CLAUDE.md` / `AGENTS.md` の「置き場所の3段」を参照） |

## 書くこと

README に次の2つの見出しが無ければ作る。

1. **最近の動き**: 新しいものを上に1行足す
   `- YYYY-MM-DD: トピック ─ 何が決まった・何ができた（できたファイルの場所）`
2. **未解決事項**: 最新にする。片付いたものは消すか `[x]` にし、新しく出たものを
   `- [ ] 誰が・何を・いつまで` の形で足す。人の判断を待っているものは頭に「判断待ち:」と付ける

## 書かないこと

- 会話の逐語録、試行錯誤の全部（要点だけ）
- パスワード・APIキー・トークンの値（置き場所だけ書く。例:「キーは `.env` の `XXX_API_KEY`」）
- お客様の個人情報・機密データ
- 雑談だけだった回は何も書かない

書いたら、更新したファイルと足した行を1〜3行で見せる。
保存（コミット）は、この書庫のやり方（枝を作る→コミット→プルリクエスト）に乗せる。
`common` の `save-to-archive` スキルがあれば使う。

## 再開の文（必ず出す）

最後に、**新しい会話にそのまま貼れば続きから始められる文**を、コードブロック1つで出す。
README を書かなかった回でも、続きがあるなら出す。前置きの説明は付けない。

```
{作業の名前}の続き。
まず読む: {更新した README の場所}（「最近の動き」「未解決事項」）{必要なら他に読むファイル}
今の状態: {どこまでできたか・まだ本番に出していないもの を2〜4行}
次にやること: {1つ目の作業を具体的に。順番があれば番号で}
決まっていること・守ること: {決まった方針、触ってはいけない所、確認を取る所}
作業する書庫: {書庫の名前と、その中のフォルダ}
```

- 次の会話は何も覚えていない前提で書く（「さっきの」「例の」を使わない。ファイルの場所・URLは省略しない）
- 鍵・トークンの値は書かない（置き場所だけ）
- 人の判断待ちがあれば「最初に聞く: …」として入れる
