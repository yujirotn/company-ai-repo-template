# slide-deck-create — スライド資料を作る

16:9 の横にめくるスライドを、**1枚の HTML ファイル**で作る（矢印キー・クリック・スワイプでめくれる、印刷すると全スライドが縦に並ぶ）。
外部の CDN・JavaScript には頼らない。画像を使う時は同じフォルダに置き、相対パスで読む。

型は `assets/deck-sample.html`（小さな見本）。**写して中身に合わせて組み立てる**。見た目の原則は `references/slide-design-principles.md`。

## 使い分け

| 求められているもの | 使うもの |
|---|---|
| めくって見せる資料（研修・発表・提案） | **このスキル** |
| 1回読んで仕組みが分かればいい1枚もの | `explain-visual` |
| PowerPoint・Google スライドのファイルで渡したい | このスキルで構成と中身を固めてから、その形式を作る道具（pptx を作るスキルなど）に移す。PDF でよければこの HTML を印刷して PDF にする |

## 0. 要件と見た目を確かめる（毎回）

作り始める前に、次を聞いて確かめる（分かっている所は聞かない）:

1. **要件**: 誰に見せるか・目的・時間・見せ方（投影だけ／受講者も手元で開く／読み物も兼ねる）
2. **見た目**: 書庫の一番上の `DESIGN.md` を読み、色・書体・ロゴ・言葉づかいをそれに合わせる
   - `DESIGN.md` に【　】が残っている項目は、勝手に決めずに1問ずつ聞いて埋める
   - お客様向けで、お客様の色に寄せるかどうか・自社のロゴを出すかどうかも確かめる

## 1. 構成を作って、承認をもらう

次の型でパートとスライドの一覧を出し、承認をもらってから中身を作る:

```
表紙 → 「今日お話しすること」3点 → [パートごとに] 扉 → 中身のスライド → … → まとめ（冒頭の問いに答える）
```

スライドの種類:

| 種類 | 使う所 | 書き方 |
|---|---|---|
| 表紙 `cover` | 最初 | 題・サブタイトル・日付・作った人 |
| 扉 `divider` | パートの始まり | パート番号＋**章の主張**＋1行の補足。全面をメインの色で塗ってよい |
| 中身 `content` | 本文 | 題（体言止め）＋1行の補足＋図・表・カード |
| まとめ `summary` | 最後 | 冒頭の「今日お話しすること」に1つずつ答える |

- 1枚に伝えたいことは1つ
- プロンプト（AI への頼み文）・手順・配布物は、全文が見える1枚にする（スライドの中でスクロールさせない）。長い一覧は配布物に回す
- 並びは「**実物 → 一覧 → 手を動かす**」。抽象的な一覧を先に出さない

## 2. 組み立てる

1. `assets/deck-sample.html` を作業用の一時フォルダに写す
2. `:root` の色の変数を `DESIGN.md` の色に置き換える
3. スライドを `<section class="slide ...">` で並べる（見本の4種類を写して使う）
4. 画像は同じフォルダの `images/` に置き、`<img src="images/…" alt="…">` で読む（`alt` に中身を書く）

### 画像を作る時（使える画像生成の道具がある時だけ）

- 指示文の型は `references/image-prompt-patterns.md`
- 画像に文字を焼き込むと、直す時に作り直しになる。**文字は HTML で書き、画像は文字なしにする**のを基本にする
- 文字を入れた画像を使った時は、**全部を1枚ずつ目で見て**、1文字の抜け・崩れも見逃さない。崩れた1枚だけ作り直す
- ロゴは AI に描かせない。会社の公式のファイル（`DESIGN.md` に場所が書いてある）を使う

## 3. 確かめる（実際のブラウザで）

`references/verification.md` の手順で、実際のブラウザで全部めくって確かめる。
**ファイルの文字を検索するだけでは合格にしない**（スライドが重なる・はみ出すのは、表示しないと分からない）。

## 4. 渡す

- ローカルで開いて本人に見てもらい、OK をもらう
- 置き場所は `CLAUDE.md` の決まりに従う（その仕事の資料の場所。例: `projects/<名前>/docs/`）。迷ったら置く前に聞く
- **外に公開する・お客様に送るのは、本人がはっきり頼んだ時だけ**。公開の前に、お客様の名前・社内の情報・個人情報が載っていないかを見る
- 書庫に入れる時は、この書庫のやり方（枝を作る → コミット → プルリクエスト）で

## やらないこと

- 角丸・影・薄い色のベタ塗りのカードで飾る（`slide-design-principles.md` の D1）
- 同じ種類のものを色で塗り分ける（D2）
- 「〜しましょう」「〜できます」の題（D3）
- 1枚に強調色を2か所以上（D4）
- 絵文字・飾りのためのイラスト
- 一覧・カタログを投影用のスライドに詰め込む（配布物に回す）
