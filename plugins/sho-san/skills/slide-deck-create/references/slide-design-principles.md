# スライドの見た目の原則

実際に作ったデッキを、書き出した PDF で1枚ずつ見て見つけた失敗から作った原則。
色・書体は `DESIGN.md` が優先。ここに書くのは、どの会社の色でも効く「組み方」。

---

## 仕上げの4点（どのデッキにも当てる）

| # | 決まり | なぜ |
|---|---|---|
| D1 | **仕上げは直角・白地・罫線**。角丸・ベタ塗りの面・影を使わない。ベタ塗りは**扉スライドの全面**と**表の見出し行**だけ | 角丸と薄い色のベタ塗りのカードは「AI が作った感じ」に寄り、中身に対して見た目が軽くなる |
| D2 | **同じ種類のものを色で塗り分けない**。両方白＋罫線にして、区別は**ラベル**が受け持つ | 比べるためだけの色分けは意味を持たない |
| D3 | **題は体言止め**。語りかけの口調にしない。「主題 ─ 述語」の型 | 「〜しましょう」「〜できます」は主張が弱く、後で読み返せない |
| D4 | **強調色は1枚に1か所**。2つ目の強調は黒の太字 | 強調が増えるほど、何も目立たなくなる |

あわせて、**絵文字を使わない・飾りのためのイラストを入れない**。図や絵は意味を持つものだけ。

`DESIGN.md` が角丸や影を使うと決めている会社では、`DESIGN.md` に従う。その時も D2〜D4 は当てる。

---

## 1. 縦を使い切れないなら、並べ方が間違っている

**症状**: 下の3〜4割が白いまま。投影すると「作りかけ」に見える。

空白は3段階で積み上がる。
```
カードの高さ > 中身    → カードの中の下が空く
カードの並びの下       → スライドの下が空く
さらにフッターまでの間 → もう一段空く
```

**下の1/3が空いたら、この順でつぶす。**

1. カードの高さを中身に合わせる（高さの固定をやめる）
2. 情報を足す（例を1つ増やす・注を1行足す）
3. 上下の真ん中に置く

**「上に寄せたまま放っておく」だけは選ばない。**

---

## 2. 日本語は3列にすると読めない

**症状**: 語の途中で折れる。「狙いが合／います」「土台／に、足していく」

**数字**: 内容の幅 1640px を間 20px で3つに分けると、1列 **約 533px**。本文 27pt で **1行あたり約 19 文字**。
日本語の1文を入れると必ず2〜3行になり、折り返しが語の途中に落ちる。

| 並べる数 | どうするか |
|---|---|
| 2 | 左右2つに分けてよい |
| 3 | **本文を1行（20 字前後）に収まるまで削る**。削れないなら3列にしない |
| 4 以上 | 文字のカードで組まない。**図（インフォグラフィック）にする** |

### 折り返しは自分で決める

ブラウザの自動の折り返しに任せない。**改行（`<br>`）の位置を自分で決める**。日本語ではこれが正しいやり方。
CSS では `word-break: keep-all;`・`line-break: strict;` を指定し、語の途中で折れにくくする。

---

## 3. 色は意味を持つ時だけ持たせる

**よい例**: 2つを比べるスライドで、カードの地を塗り分けるのをやめて両方白にした。
すると、**色はラベルだけが受け持つ**形になった（左＝「これまで」／右＝「これから」）。

- 背景を塗り分けない。**区別はラベルと罫線で**
- **強調色は1枚に1か所**。2つ目の強調は黒の太字にする
- 状態や確からしさの区別は、色ではなく**罫線の濃淡＋文字**で（白黒で印刷しても消えない）

---

## 4. 題は「主題 ─ 述語」の体言止め

```
○  アーティファクト ─ 返ってくるものが変わる
○  頼み方ごとの向き不向き ─ チャット と エージェント
×  アーティファクトを使ってみましょう
×  エージェントならこんなことができます
```

- **語りかけの口調にしない**
- **題だけ読めば、その章の主張が分かる**形にする
- サブタイトル1行で補う。サブタイトルは主張の理由か、読み方の案内

---

## 5. 中身の種類 → 見せ方

| 中身 | 見せ方 |
|---|---|
| **できる・できない、分類（3行以上）** | **表**（見出し行を塗る＋行ごとに薄い地を交互に）。一番うまくいきやすい型 |
| 2つを比べる | 左右2つに分ける。地は塗らずラベルで区別 |
| 考え方・つながり・流れ | 図（ページ内の SVG か、生成したインフォグラフィック） |
| 実例 | 上に実物のスクショ、下に再現するためのプロンプト |
| 前と後 | 2枚を並べ、下にプロンプト |
| 手順 | 番号付きの段 |
| **一覧・カタログ** | **スライドに載せない。配布物に回す** |

### 最後の行がいちばん大事

5行×2枚に長いプロンプトを詰め込むと、注がフッターに重なって読めなくなる。
**カタログは紙で配るものであって、投影するものではない。**
スライドには代表を3つだけ抜き、残りは配布の PDF に回す。

---

## 5-b. 操作の案内は「スクショに枠と番号を焼き込み、本文の番号の説明と合わせる」

生のスクショを貼るだけでは、どこを見ればよいか伝わらない。**画像に強調色の枠＋番号を焼き込み、スライドの下（か右）の番号付きの説明と一対一で合わせる。**

| | |
|---|---|
| 枠 | 強調色の直角の四角。線の太さ 5px（2倍の解像度で焼く時） |
| 番号 | 強調色で塗った正方形（44px）＋白い数字。枠の**左脇**に置く。左に余白が無ければ枠の上、それも無理なら右 |
| 余白 | 番号を置くために、切り抜く時に**左へ 40〜60px の白を足す** |
| 説明 | スライド側の HTML で書く。**画像に説明文を焼き込まない**（直せなくなる） |

**切り抜きは要点だけに寄せる。** 画面全体を貼ると真ん中が大きく空き、スライドの上で小さくなる。

**枠が3つ以上なら、画像を左・番号の説明を右の2列**にする。横一列の説明は4つ以上で日本語が読めなくなる（→ 2）。

焼き込みは画像を扱う道具（Python の Pillow など）で行う。番号の置き場所を決める処理（左に余白があれば左、無ければ上・右）を関数にしておくと使い回せる。

---

## 6. 並びは「実物 → 一覧 → 手を動かす」

**抽象的な一覧を先に出さない。** 実物を1つ見せてから、ほかにもあると広げ、最後に自分でやってもらう。

```
○  実例（実物のスクショ）→ プロンプトの一覧 → 実際にやってみる
×  プロンプトの一覧 → 実例 → 実際にやってみる
```

---

## 7. 扉は「章の主張」を書く場所

- 扉はメインの色の全面。ラベル（PART n）＋見出し＋サブの3点
- **写して作ったら、ラベル・見出し・サブを必ず差し替える**（前の章の文言のまま残る失敗が多い）
- **扉の見出しと、次のスライドの題を重ねない**
  - 直した例: 扉「道具づくり ─ 触れるものが返ってくる」／次「つくり方 ─ 日本語で頼むだけ」

## 確かめは機械でやる

「ほかにもはみ出しているスライドがあるか見て」を目で探すと、取りこぼす。同じ点検を機械でやれば数秒で全部出る。
**目で見るのは「読めるか・伝わるか」を判断するため。はみ出しや重なりの検出は機械に任せる。** 手順は → `verification.md`
