# doc-kit — 同じ中身を、縦と横の2つの形で

1つの中身から、**縦（A4・印刷して配る）** と **横（16:9・映して話す）** の2つを作る。
どちらも1ファイルで完結する HTML。外部の CDN・JavaScript には頼らない（書体だけ Google Fonts 可）。

見本は `assets/` の2つ。**写して中身に合わせて組み立てる**（見本の文言は全部差し替える）。

| ファイル | 中身 |
|---|---|
| `assets/tate-sample.html` | 縦（A4）の見本: 表紙 → 会社概要 → 流れ図（DFD） |
| `assets/yoko-sample.html` | 横（16:9）の見本: 同じ3ページを横長に組み直したもの |
| `references/page-types.md` | ページの型（会社紹介・戦略共有・流れ図）と、図の記号の約束 |
| `scripts/shot.py` | 全ページを撮って、ページからのはみ出しを数える |

## 使い分け

| 求められているもの | 使うもの |
|---|---|
| 同じ中身を「配る用」と「映す用」の両方で欲しい。会社紹介・戦略共有・仕組みの説明 | **このスキル** |
| 1回読んで分かればいい図解1枚だけ | `explain-visual` |
| 研修・発表でめくるスライドだけ（枚数が多い・話の流れが主役） | `slide-deck-create` |
| 見た目の点検・手直しだけ | `visual-design` / `design-review` |

## 0. 会社の決まりを読む（毎回）

1. 書庫の一番上の `CLAUDE.md`（置き場所・守ること）と `DESIGN.md`（色・書体・ロゴ・使わないもの）を読む
2. `DESIGN.md` に【　】が残っていて、色・ロゴの場所が決まっていない時は、勝手に決めずに1問ずつ聞いて埋める
3. 色は**役割で**使う: 文字と線の色・薄い線の色・地の色・**強調の色（1種類だけ）**。強調の色は1ページに1か所

## 1. 形と種類を決める（1問ずつ）

1. **形**: 縦だけ／横だけ／両方（迷ったら両方。縦で中身を固めてから横に組み直す）
2. **種類**: 会社紹介／戦略共有／仕組みの図解（データの流れ図）／その他。型は `references/page-types.md`
3. **誰に・どこで**: 読み手（社内・取引先・お客様）と、見せ方（印刷して配る・投影・URL で送る）
4. **材料**: 議事録・数字・過去の資料・会社のホームページ。**数字・実績・沿革は材料にあるものだけを使い、作らない**

## 2. 絵コンテで合意する（作る前に）

全ページを1つの表で出し、OK をもらってから作る:

```
| No. | 見出し（言い切りの1文） | 主役の図（種類） | 材料（何を・どこから） |
```

- 見出しの列だけを上から読んで、話が通るかを先に確かめる
- 表紙・締め以外は、全ページに**主役の図を1つ**（流れ図・比べる表・はしご・数字・アイコンの並び）。文章を主役にしない
- 材料が無い所は「空欄にする」と書いておく（ここで中身を作らない）

## 3. 組み立てる

1. `assets/` の見本を作業用の場所に写す（縦・横の両方なら両方）
2. `:root` の色の変数を `DESIGN.md` の色に置き換える。ロゴの `src` を `DESIGN.md` に書いてあるロゴのファイルにする（ロゴは AI に描かせない・似せて作らない）
3. ページの型に中身を入れる
   - **縦**: 1ページ＝A4（210×297mm）。上に小さな見出し → 言い切る大きな見出し → 1〜2行の前置き → 図 → 表・カード
   - **横**: 1枚＝1280×720。**同じ中身を横長に組み直す**（縦の図を縮めて置かない。流れ図なら上→下を左→右に描き直す）。題は「主題 ─ 述語」の体言止め、前置きは1行まで
   - 縦で1ページに入った中身が、横で1枚に入りきらない時は、枚を分ける（言葉の説明・対応表は最後の1枚へ）
4. **分からない中身は点線の空欄**（`<span class="blank"></span>`）で残す。「？」「（推測）」「ここに入れる」とは書かない
5. 絵が要る時は、ライセンスの明確なアイコン集（Lucide・Tabler などの MIT）の SVG を埋め込み、色は文字の色に合わせる

### 見た目の決まり（どの会社でも守る）

- 角丸・影・薄い色のベタ塗りのカードを使わない。区切りは罫線だけ（`DESIGN.md` が許す時を除く）
- 飾りの線（見出しの横の短い線・意味のない枠）を入れない。線は表と図の中で意味を持つ時だけ
- 見出しは本文の2倍以上の大きさ。余白は決めた数段（例: 8/16/24/40px）だけ
- 同じ種類のものを色で塗り分けない。区別はラベルで
- 絵文字・飾りのためのイラストを使わない

## 4. 撮って、自分の目で確かめる（省略しない）

```bash
python3 scripts/shot.py <作ったHTML> <画像の出力先> --kind tate   # 縦（A4）
python3 scripts/shot.py <作ったHTML> <画像の出力先> --kind yoko   # 横（16:9）
```

- 全ページの画像ができる。**1枚ずつ開いて目で見る**（文字の検索だけで合格にしない）
- 「はみ出し」が出たページは、A4・16:9 の枠を超えている。文字を削るか、図を小さくするか、ページを分ける
- 見る所: 文字が枠や図の線と重なっていないか／線どうしが交差していないか／強調の色が1か所か／空欄が空欄のまま残っているか／下半分が大きく空いていないか（空いていたら文字を大きくするか、図を足す）

## 5. 渡す

- 置き場所は `CLAUDE.md` の決まりに従う（その仕事の資料の場所。例: `projects/<名前>/docs/`）。迷ったら置く前に聞く
- 縦は、ブラウザの印刷で「PDF に保存」すれば、そのまま A4 の PDF になる（余白なし・背景のグラフィックを入れる）
- 横は、そのまま映すか、印刷で 16:9 の PDF にする
- 空欄が残っている時は、渡す時に「どこが空欄か」を一覧で伝える
- **外に公開する・お客様に送るのは、本人がはっきり頼んだ時だけ**。その前に、ほかの会社の名前・社内の数字・個人情報が載っていないかを見る
- 書庫に入れる時は、この書庫のやり方（枝を作る → コミット → プルリクエスト）で

## やらないこと

- 材料に無い数字・実績・沿革・人の名前を作る
- 縦の図をそのまま縮めて横に貼る（横長に描き直す）
- 1ページに強調の色を2か所以上使う
- 絵コンテで合意する前に作り始める
