# 現地での進め方（研修・訪問の場で回す時）

## 誰と回すか
- **決める人**（その環境の持ち主・責任者）が必ず同席する。決定木の答えは決める人から取る
- 実際に使う人（1〜3人）が同席すると、論点 1・8・9・11 の「実際に使っているか」が速く確かめられる
- AI の操作は、相手の端末で相手の AI に頼む形を基本にする（こちらの端末で相手の環境を触らない）

## 30分版（研修の1コマ）

点検 → グリル → 決定ログ だけをやる。作り直し（③ 以降）は持ち帰り。

| 時間 | やること |
|---|---|
| 0〜10分 | ① 点検（SKILL.md の「① 点検の頼み方」）。待ち時間に論点 1「仕事の領域」を口頭で聞く |
| 10〜25分 | ② グリル。点検で一番低かった柱に当たる論点を2〜3個（`決定木.md` の冒頭の表） |
| 25〜30分 | ⑦ 決定ログ。決まったこと・持ち帰りを表にして見せる |

AI にはこう頼む:

```
/sho-san:org-rebuild の30分版で進めて。
まず harness-check で点検し、点数の一番低い柱に当たる論点を2〜3個、1問ずつ推奨つきで聞いて。
最後に決定ログを表で見せて（書庫に保存するのは私が OK してから）。
```

点検に時間がかかって10分を超えたら、点検を待たずに論点 1・2 から始めてよい。

## 半日〜1日版（合計 3〜4 時間。2日に分けてもよい）
| 段階 | 目安 | メモ |
|---|---|---|
| 最初の確認（下のチェックリスト） | 15分 | ここで止まる項目があれば先に解決 |
| ① ハーネス点検 | 15〜20分 | 相手の AI が走らせる。待ち時間に決定木の A を口頭で始めてよい |
| ② グリル A〜B（論点 1〜8） | 60分 | 1問ずつ。表を見せる論点（7・11・13）は時間がかかる |
| ② グリル C〜E（論点 9〜18） | 45分 | 相手が使っていない仕組みは飛ばす |
| ③ 移行表 → ④ コピーと照合 | 30〜60分 | 容量しだい。コピーの待ち時間に ⑤ の準備 |
| ⑤ 別の目の点検 → 指摘の対応 | 30〜45分 | 2人を同時に走らせる（各5〜10分） |
| ⑥ 公開・同期 → ⑦ 決定ログ → ⑧ 再点検 | 30分 | ⑧ の点数の変化で締める |

時間が足りない時の優先: ① → ② A〜B → ⑦ を今日やり、③ 以降は持ち帰り。

## その場で決めきれない論点
- 「持ち帰り」と言って次に進む。決定ログの「持ち帰り」欄に「論点・誰が・いつまでに・決めるのに要る材料」を書く
- 持ち帰りが前の論点の答えに依存する場合は、その下の論点も一緒に持ち帰る（推測で埋めない）

## 最初に確認する項目（チェックリスト）
相手の端末・権限・保存先が分からない前提で、始める前に確かめる。30分版なら最初の3つだけでよい。

- [ ] 使っている AI は何か（Claude Code ／ Codex ／ 両方）。バージョン
- [ ] 作業環境のフォルダはどこか（書庫か、ただのフォルダか）。容量と `.git` の有無
- [ ] 今日中に終わらせたい範囲（30分版か、①〜⑧ のどこまでか）
- [ ] GitHub 等のアカウントはあるか。Private の書庫を作れるか（会社のルール）
- [ ] 保存先（Google Drive・Box・OneDrive など）は何か。手元から見えているか。空き容量
- [ ] PC の管理者権限はあるか（gitleaks などの道具を入れられるか）
- [ ] 会社のセキュリティ規程: 取引先の個人情報を GitHub に置いてよいか、パスワード管理ツールを AI に読ませてよいか
- [ ] 端末は人が前にいて使うか、離れた場所から操作するか
- [ ] 定期で動いている自動の仕事（クラウドの定期実行・cron・launchd）はあるか
- [ ] 他の人や別の AI の会話が同じ環境を同時に触っていないか（触っていたら先に止める・知らせる）

## やってはいけないこと
- 相手の答えを推測で埋めない。音声入力の聞き違いは聞き返す
- 照合前に「移せました」と言わない
- 古い環境の削除・archive を、相手の明示の OK と保存先のクラウド反映の確認なしにやらない
- 相手の秘密情報（パスワード・トークン・カード番号）を画面・ログ・ファイルに出さない
