# UXレビューの原則

画面を判定する時の物差し。よく知られた画面設計の原則と、業務ツールでよく見る工夫を、レビューで使う12の観点に束ねた。
各観点の「チェック」は、画面を見て はい／いいえ で答えられる問い。「いいえ」が付いたら、直すべき点の候補。

## 下じきにした考え方

- Apple Human Interface Guidelines の「デザインの原則」（公開資料。https://developer.apple.com/design/human-interface-guidelines/ ）
- 段階的に見せる（progressive disclosure）・認知負荷を下げる、という画面設計の一般的な考え方
- 仕事の管理ツール（タスク管理・顧客管理など）でよく見る工夫: 最初の画面を「自分のやること」に絞る、今やらない項目は折りたたむ、状態は色と文字の両方で示す

## 8つの原則（要約）

| 原則 | ひとことで | レビューでの読み替え |
|---|---|---|
| 目的 | 意味のあるものを作る。一番大事な機能に集中する | この画面の主な作業は何か、それが一番目立っているか |
| 主体性 | 邪魔をしない。自由に動けて、ミスから簡単に戻れる | 余計な手順に縛られないか、取り消せるか |
| 責任 | 何をなぜ行うかを正直に示し、情報を守る | 送信・通知・公開など「外に出ること」を先に示すか |
| 親しみやすさ | 知っている考え方を使い、見た目と動きをそろえ、反応をはっきり返す | 言葉・配置・反応がそろっているか |
| 柔軟性 | いろいろな人・入力・画面の幅に合わせ、文脈を保つ | 幅を変えても位置が予想できるか、キーボードで使えるか |
| シンプルさ | 必要なものだけを入れ、簡潔にし、階層を作る。シンプル＝何も無い、ではない | 大事なものを近くに、それ以外を遠くに置いているか |
| 作り込み | 細部が品質の印象を決める | 文言・状態表示の細部が崩れていないか |
| 喜び | 喜びと飾りを取り違えない。業務ツールは控えめでよい | 演出が作業の邪魔をしていないか |

## 12の観点

### U1. 今やることが5秒で分かる
- チェック
  - 画面を開いて5秒以内に「次に自分がやること」を1つ言えるか
  - 最初の画面が全件の一覧ではなく、自分に関係するものに絞られているか
  - 「今日・近日・あとで」のように時間で区切られ、手を付ける順番が分かるか

### U2. 1画面の情報量が抑えられている
- チェック
  - 最初に見える範囲に、同じ強さで目立つボタンが並びすぎていないか（目安は下の「計測の目安」）
  - 今やらない項目は、折りたたむか別の場所に置かれているか
  - 同じ情報が2か所以上に重なって出ていないか
  - 詳しい画面は「概要 → 時系列 → 関連」の順で、上から読めば足りるか

### U3. 状態が一目で、正しく読める
- チェック
  - 状態（完了・期限切れ・待ち）を、色だけでなく文字や形でも示しているか
  - 警告の印が多すぎて、本当に急ぐものが埋もれていないか（全部に赤が付いていないか）
  - 期限切れは「通知を増やす」のではなく、該当するものに静かに印を付けているか
  - 押せるものと押せないもの（無効）を見間違えないか

### U4. やることまでの手数が少ない
- チェック
  - 主な作業が、一覧から3操作以内で終わるか
  - 一覧と詳しい画面を何度も行き来しないと判断できない作りになっていないか
  - よく使う操作が、遠くのタブや奥のメニューに隠れていないか

### U5. ミスを防ぎ、すぐ戻れる
- チェック
  - 取り返しのつかない操作（中止・送信・削除）に、確認か取り消しの手段があるか
  - 理由の入力などの「止め」が、本当に必要な操作だけに付いているか（全部に付けると、読まずに押すようになる）
  - 間違えて完了にした時に、元に戻す方法が見えているか

### U6. 判断の材料がボタンの前にある
- チェック
  - ボタンを押す前に、押すと何が起きるか（誰に知らせが行くか、何が変わるか）が見えるか
  - ボタンの文言が「OK」「確定」ではなく、結果を表す言葉か
  - 1画面に、同じ強さの主なボタンが2つ以上並んでいないか

### U7. 使う人の言葉で書いてある
- チェック
  - 作り手の用語（内部の状態名・コード名・版の番号）がそのまま出ていないか
  - 数字や期限に「だから何をすればいいか」が添えられているか
  - 初めて見る人に、説明なしで通じる言葉か

### U8. そろっている
- チェック
  - 同じ種類の操作が、どの画面でも同じ場所・同じ形・同じ言葉か
  - 同じ色が、画面によって違う意味で使われていないか
  - 画面の幅を変えても、主な要素の位置が予想できるか

### U9. 行き止まりがない
- チェック
  - 0件・エラー・権限がない時に、次に何をすればいいかが示されるか
  - 操作できない理由（前提がそろっていない等）が、その場で分かるか
  - 操作した後に「次に何が・いつ起きるか」が示されるか

### U10. 外に出ることを先に示す
- チェック
  - チャットへの投稿・相手への招待・メール送信など、画面の外に何かが出る操作は、押す前にそれが分かるか
  - 誰が見られる情報か（社内だけ・相手にも）が分かるか

### U11. 画面の外まで流れがつながる
- チェック
  - メールやチャットの通知から画面に来た時、その件・その作業にそのまま着くか
  - 画面で操作した結果が、通知を送った側でも分かるか（二重に確かめさせないか）

### U12. 初めての人と慣れた人の両方が困らない
- チェック
  - 初めての人に、まずやる1つのことが示されているか
  - 慣れた人の作業を、初めての人向けの説明が毎回邪魔していないか
  - スマホで使う操作は、指で押しやすい大きさ（目安 44×44 以上）か

## 計測の目安（`scripts/ux_measure.py` の値の読み方）

数値は「超えたら必ずダメ」ではなく、**目で見て確かめるきっかけ**。最後の判定は、目で見たことと、つまずく場面で行う。

| 計測値 | 目安 | 超えたら見ること |
|---|---|---|
| 最初に見える範囲のボタン数（`buttons`） | 1280px で15個前後まで | 今やらない操作が並んでいないか（U2） |
| 最初に見える範囲の「強調」の数（`emphasis`。赤・警告色・太い枠） | 全体の2割以下 | 全部が警告になっていないか（U3） |
| 最初に見える範囲の文字数（`text_chars`） | 1280px で600字前後まで | 読ませすぎていないか、折りたためないか（U2） |
| 12px 未満の文字（`small_text`） | 0件が望ましい | 読めない注記・状態表示がないか（U12） |
| 44px 未満の押せる場所（`small_targets`。375px で見る） | 主な操作では0件 | スマホで押し間違えないか（U12） |
| 色の種類（`colors`。文字・背景の実際の色） | 8色前後まで | 1色1意味が崩れていないか（U3・U8）。会社の `DESIGN.md` の色と照らす |
| 横スクロール（`body_scroll_x`） | false | はみ出している要素がないか |

## 画面だけでは判定できないこと

「どう作るか・どう試すか」の原則（実際に使う人に早めに試作を触ってもらう、少人数で何度も試す、など）は、画面のレビューでは直すべき点にせず、結論の最後に**提案**として添える。
例:「実際に使う人3〜5人に、試作で『今日やること』を探してもらう」
