# 確かめ方（省略しない）

図解は「見て分かる」ことがすべて。**文字の検索・DOM の点検だけで合格にしない。**
日本語の折り返しの崩れ・SVG の文字のはみ出し・図の意味の破綻は、目で見ないと分からない。

## 1. 撮る（1280px と 375px）

```bash
python3 <このスキルの場所>/scripts/shot.py "<作ったHTML>" "<スクショの出力先>"
```

- スクショの出力先は、**作業用の一時フォルダの絶対パス**を渡す（相対パスにすると、今いるフォルダ＝書庫の中に画像が散らかる）
- 必要なもの: `playwright`（Python 版）。入っていなければ `pip install playwright && python3 -m playwright install chromium`
- 手元のファイルを手元のブラウザで開いて撮るだけで、外へは何も送らない

スクリプトが機械的に拾うのは4つだけ:

| # | 見つけるもの | 意味 |
|---|---|---|
| 1 | ページ全体の横スクロール | 並べ方が崩れている |
| 2 | 許した入れ物の外での、はみ出し | SVG や表が画面から飛び出している |
| 3 | 壊れた画像 | `<img>` の読み込み失敗 |
| 4 | `aria-label` の無い SVG | `diagram-patterns.md` の必須の決まりに反している |

`.roadmap-scroll` と `.table-scroll` の中は、**わざと横にスクロールさせる作り**なので除いている。

## 2. 目で見る（ここが本番）

出てきた PNG を**開いて実際に見る**。見る点:

| 見る点 | だめだった時 |
|---|---|
| 図の文字が枠から出ていないか | ノードの名前を全角8文字以内に縮める（文字を小さくしない） |
| 375px で図が読めるか | `.compare-box` を `.roadmap-scroll` に替える |
| 矢印が交差していないか | ノードの並び順を変える（交差がゼロになるまで） |
| 図だけ見て流れが追えるか | 追えないなら図の失敗。文章を足すのではなく**図を描き直す** |
| 強調色が3か所以上ないか | 一番大事な1つに絞る |
| 専門の言葉に、初めて出た所で説明があるか | 言葉の説明の欄か、括弧の説明を足す |
| 1〜5 の説明文が 800 字を超えていないか | 図で言えていない印。文章を削って図に移す |

## 3. 中身の裏をとる（②自社のシステムの時だけ）

**図に描いた構造が実物と同じか**を、図を見ながらもう一度ソースに当てる。

- 描いたノードが、本当にあるファイル・表・関数か
- 描いた矢印の向きに、本当にデータが流れるか（呼ぶ側と呼ばれる側が逆になっていないか）
- 読めていない所を「たぶんこう」で描いていないか → **未確認と書く**

> 実物と食い違う構成図は、無いより悪い。間違った地図を読んだ人の頭に焼き付ける。

## 4. 残す

- 確かめて直した点で、次に同じ型を使う時に役立つものは、`diagram-patterns.md` の「SVG の落とし穴」に足すことを提案する
